## Findings and disposition

- **High, unresolved — R2/R3 stable identity reuse and stale ACK mapping.** Preserve the failing cases in [`review_integrity_test.py`](../../tools/cloud_phase0/review_integrity_test.py); fix and rebaseline as a new candidate before a new independent review.
- **High, unresolved — R7 corrupt committed first-loss fallback.** Preserve the failing case in [`review_integrity_test.py`](../../tools/cloud_phase0/review_integrity_test.py); make the ambiguous loss/sequence state read-only or otherwise prove it cannot hide a committed loss or reuse its ordinal.
- **Medium, unresolved — R6/R8 cut evidence.** Wire journal cut injection through loss recording and directly assert loss-ACK metadata cuts before claiming every transition is covered.
- **Medium, unresolved — R10 counter bounds.** Validate cumulative loss counter widths before erasing or programming either emergency sector, and define the full-counter behavior.
- **Medium, unresolved — readiness newline portability.** Serialize canonical JSON bytes independently of host text newline translation, then deliberately rebaseline the expected hash. The reviewed evidence is semantically stable, but the required verifier is currently ineligible on this host.

The clean-room verifier's `4/4` focused pass and `51/51` frozen host matrix do not close these manual findings. The physical host/target boundary remains explicit: this decision addresses a host model only and is not ESP32-S3 flash-driver, brownout, wear, timing, GNSS/LED, energy, or field-safety evidence.
