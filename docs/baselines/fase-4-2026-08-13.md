# Baseline de Fase 4 — 2026-08-13

Este registro acompaña el plan de [`RGB Dog × WLED`](../analisis-wled-y-plan-implementacion.md). La Fase 4 entrega escenas pequeñas, reproducción Show por catálogo, persistencia A/B y una API estricta. Está completa en software; la aceptación HIL/física continúa pendiente.

## Resultado

El pipeline conserva la autoridad del producto y agrega una receta visual antes de composición:

```text
SceneCatalog + ScenePlayer ── snapshot opcional ──┐
GPS / Wi-Fi / Home / Day Mode / config ──────────┤

                                                  ↓
```

## Contrato de escenas

- `SceneV1` schema 1 y wire canónico de 44 bytes.
- Cuatro built-ins inmutables: Alta visibilidad, Calmado, Activo y Fiesta.
- Cuatro slots de usuario con IDs `128..131`.
- Nombre UTF-8 de hasta 23 bytes, reservados/flags estrictos y validación effect/paleta/mirror/safety.
- `body_level` de `1..255` escala solo el cuerpo; brillo global, status, alertas y limitador conservan autoridad.
- Built-ins, schema, record y registries tienen ejes de versión separados.

Los built-ins congelados son:

| ID/key | Effect + paleta | Speed/intensity | Nivel | Transición |
|---|---|---:|---:|---:|
| `1/high_visibility` | Chase + Safety Amber | 120/180 | 255 | 400 ms |
| `2/calm` | Breath + Night Red | 45/100 | 110 | 900 ms |
| `3/active` | Comet + Forest | 140/170 | 200 | 500 ms |
| `4/party` | Rainbow + Pride | 150/180 | 180 | 650 ms |

## Persistencia y recuperación

`SceneBankRecordV1` ocupa 196 bytes y contiene generación, schema, máscara, cuatro escenas y CRC-32/IEEE. `SceneStore` alterna `scene_a`/`scene_b` bajo `dogrgb_scn`, confirma por readback y no escribe en no-op.

La matriz nativa cubre bancos ausentes, cortos, corruptos, futuros, sobredimensionados y ambiguos; fallos de read/write/readback; primer write; delete/replace-all; wrap de generación; cada corte posible entre 0 y 195 bytes; y 1.000 secuencias deterministas con cortes/fallos. Un record futuro queda read-only. Una recuperación corrupta/ambigua es explícita y restaura dos copias equivalentes.

El fallo del store de escenas no impide arrancar los cuatro built-ins, GNSS, Wi-Fi ni LEDs.

## Player, política y Show

- Apply/cancel usan un comando fijo consumido en el tick; no escriben flash.
- El último comando gana y un apply manual produce `LedIntent::SceneManual` sin modificar el modo persistido.
- El player conserva snapshot, generación aplicada y flag `stale`.
- Show usa una bolsa fija de ocho bytes, recorre cada escena elegible una vez y evita repetición entre bolsas.
- La permanencia es 30 s; Welcome y Day Mode pausan el tiempo activo.
- Cambiar el modo cancela el override; reaplicar reinicia runtimes y transición.
- El Show aleatorio anterior se eliminó: no quedan dos motores de reproducción.

Los tests prueban prioridad con Welcome, Day Mode, System/Geofence, snapshot stale, último comando, `millis()` wrap y que `body_level` no modifica status/alerta.

## API y límites

Rutas entregadas:

```text
GET  /api/v1/led/scenes
POST /api/v1/led/scenes/apply
POST /api/v1/led/scenes/cancel
POST /api/v1/led/scenes/save
POST /api/v1/led/scenes/delete
GET  /api/v1/led/scenes/export
POST /api/v1/led/scenes/import
```

Las mutaciones requieren CSRF, PIN opcional, `application/json`, `Content-Length` entre 2 y 4096 y nesting máximo 6. El collector valida esos límites antes de reservar/copiar el body raw. Multipart/form no son formatos válidos. El límite 6 es intencional: el documento canónico importado anida hasta `document.scenes[].branch.effect.id`.

Save/delete/import usan generación esperada; import es replace-all y ofrece `dry_run`/recuperación explícita. Export usa allowlist y no contiene SSID, passwords, PIN, Home, coordenadas, geofence ni perfil eléctrico. State, capabilities y `/api/dev` se ampliaron de forma aditiva.

La UI gráfica de edición no pertenece a esta fase; queda para Fase 5B.

RAM queda bajo el gate de +1 KiB. Flash excede la estimación inicial de +20 KiB; [ADR-0003](../adr/0003-scene-model-and-store.md) aprueba un límite revisado de +32 KiB porque los 29.256 B incluyen la validación JSON estricta, siete rutas, errores y diagnósticos. No se relajó el contrato para ocultar el delta.

El payload durable máximo sigue siendo 392 B para dos records de 196 B. Los números de build no demuestran consumo transitorio de heap ni latencia NVS.
