# Display I3 — simple text LCD

Date: 2026-09-12. **Software implemented and locally verified; physical I0–I3
acceptance remains open.** Started with a clean tree at
`b80ed92c8b0b3f83f94beab067a3c63f6f63b768`. This record describes local I3
changes on that commit. No board was flashed or measured. The owner's request
to advance the plan authorizes this software increment while earlier physical
gates remain visible.

## Delivered behavior

- Waveshare product now has the basic text LCD. A seventh target,
  `waveshare_lcd169_displaycheck`, adds I3 diagnostic controls while retaining
  I2 LED limits and the normal GPS/LED/portal/persistence core. Product has no
  diagnostic commands or bench overrides. Classic and I0–I2 remain LCD-free.
- One ST7789/SPI owner, explicit candidate pins, 240×280 portrait, offsets
  `0,20,0,0`, IPS inversion and initial 40 MHz SPI. Arduino_GFX 1.6.7 is pinned
  only in the two display-enabled targets; the core and other libraries remain
  unchanged. No LVGL, framebuffer, sensor, new partition or schema.
- A value-only `DisplaySnapshot` adapter reads existing GPS and LED state.
  A separate text formatter preserves trust/validity, daily distance and
  recorded date. Invalid speed is `--`; valid zero remains zero. Five changing
  rows use stable positions, a prominent speed value and explicit status text.
- One initialization attempt at the end of normal setup; backlight follows the
  complete first frame. Known driver failure disables only UI operation.
  Normal sampling is capped at 1 Hz and transfers at most one changed row per
  loop after HTTP, with GPS first. Unchanged formatted values are not redrawn.
- Stage 3 USB controls: `t` bars/border, `v` live view, `b` backlight toggle,
  `d` service pause/resume, `r` reset display timing counters. Eight characters
  maximum per loop; no LED commands or USB-disconnect stop. Normal queued logs
  expose sample/pending rows, init time, drawing count, maximum service time and
  a bucket-based p95 upper bound for drawing ticks.

Implementation, electrical sources, semantics and the physical procedure are
in the [I3 guide](../../Platformio/Dog-RGB/docs/display-i3.md). The official
No Touch demo was read from its archive, including the HelloWorld sketch and
`Mylibrary/pin_config.h`; it was not copied as an application or used to replace
our core. Archive SHA-256:
`b5dcaa0f524fa17dbf670c071e11e777a5d450aaf8eb506f2ed27e912e74a90e`.
Exact driver source references are linked in that guide.

## Verification

Windows, PlatformIO 6.1.19, Python 3.11.9 and native `g++`; CI remains Python
3.13. Existing pinned pioarduino 55.03.311, Arduino 3.3.11/IDF 5.5.5,
ArduinoJson 7.4.3 and NeoPixel 1.15.5 are preserved. Commands from the firmware
directory:

```powershell
pio run -e seeed_xiao_esp32s3 -e wokwi -e waveshare_lcd169 -e waveshare_lcd169_bringup -e waveshare_lcd169_ledcheck -e waveshare_lcd169_gpscheck -e waveshare_lcd169_displaycheck
python -m unittest discover -s test -v
```

**7/7 environments compile and the final suite passes 140/140 tests**, with no
compiler warnings/errors in target builds. Waveshare product was rebuilt after
the final service-timing instrumentation change; both display ELF files contain
that instrumentation. The initial full host run hit a Windows executable-file
lock during temporary-directory cleanup in an existing board test; the full
rerun after compilation passed without changing that test's cleanup behavior.
The new native harness scopes suppression of pre-existing unused AP constants
to `config.h`, retaining `-Werror` for code under test.

The native display test executes the actual adapter, formatter and scheduler
with fake domain getters/clock/Print and a recording GFX transport. It verifies
pin/window arguments, first-frame/backlight order, one initialization attempt,
detected failure without retries, valid zero, invalid/nonfinite speed, quality
states, retained daily value/date, long-value formatting, mode names, text
bounds, unchanged-row suppression, one row per tick, 1 Hz including rollover,
bounded USB commands, backlight versus service pause and timing-counter reset.
The real LED bus/limiter harness now runs for stages 2 and 3. Existing GPS,
LED, persistence and other host checks remain in the common suite. Source
contracts check setup/loop ordering and queued reports.

Seven package inventories and defined ELF symbols were checked. Only Waveshare
product and I3 contain ST7789/display code and the graphics dependency. Product
binaries exclude `bringup::`; I0/I1 exclude normal GPS/LED policy/storage;
I2 and I3 contain the normal core and GPS diagnostic, with no I1 controller or
welcome. CI's seven-target matrix and local documentation links validate; no
remote GitHub Actions run is claimed.

Three 240×280 layout previews (searching, fix, stale) were rendered locally
using the actual drawing/formatting code and installed driver bitmap font with
a rasterizing fake transport. The fix and stale outputs were visually inspected:
text fits, units/positions remain stable and stale speed clears while distance
stays. These previews are **not** LCD photographs, SPI timing measurements or
the future LVGL simulator. Raw evidence and the local preview recipe live in
ignored `Platformio/Dog-RGB/artifacts/display-i3/`.
