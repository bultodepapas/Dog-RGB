# Display I2 — existing GPS with normal LED policy

Date: 2026-09-12. **Software implemented and locally verified; physical I0–I2
acceptance remains open.** Work started with a clean tree at
`4293f4c72cdfbf26816d7cd21f6e5c1686e421a3`; results describe the local I2 changes
on that commit. No device was flashed. This prepares the next increment under
the owner's instruction to continue, without closing earlier physical gates.

## Implementation

`waveshare_lcd169_gpscheck` selects stage 2 in the same `main.cpp`, using normal
storage/configuration, GPS, geofence, LED policy, BLE/Wi-Fi and portal ordering.
It adds only `bringup/gps_check.cpp`; I1 patterns and their driver are excluded.
Welcome is omitted. Every LED bus brightness request is capped at 16/255; the
current estimator is enabled with a maximum 1000 mA budget. Lower requests and
calibration coefficients are respected. Only transport settings are capped:
the diagnostic never saves those overrides, while ordinary configuration and
GPS metric/route/session persistence continue unchanged. Normal LED mode,
Day Mode and scene rules remain in effect.

A bounded `[I2]` report uses the normal serial queue, at the existing 600 ms
interval. It contains typed reception state, raw/trusted flags, valid speed,
recorded daily distance/date, quality, observed ages, counters and effective
LED limits. Invalid speed prints `--`; valid rest prints `0.00`. A small pure
GPS reception helper shares the existing 3000/5000 ms strict expiry thresholds
with the parser. Parser, trust filters and accumulation rules are preserved.

Unlike I1, this full-core diagnostic continues without USB and has no I1
commands or automatic stop. It introduces no LCD/library, configuration schema,
partition migration, new effect or second UART/parser. See the
[board guide](../../Platformio/Dog-RGB/docs/boards.md) for operation and wiring.

## Verification and limits

Windows, PlatformIO 6.1.19, Python 3.11.9 and native `g++`; CI remains Python
3.13. Pinned platform 55.03.311, Arduino 3.3.11/IDF 5.5.5, NeoPixel 1.15.5 and
ArduinoJson 7.4.3 are unchanged. From `Platformio/Dog-RGB`:

```powershell
pio run -e seeed_xiao_esp32s3 -e wokwi -e waveshare_lcd169 -e waveshare_lcd169_bringup -e waveshare_lcd169_ledcheck -e waveshare_lcd169_gpscheck
python -m unittest discover -s test -v
```

**6/6 builds and 137/137 host tests passed**, with no compiler warnings/errors.
The initial host run exposed a source-location assertion for the extracted age
helper; it was updated to check the helper and both parser calls, retaining
the existing rollover/observation checks. The full suite then passed.

The new native harness executes the reception classifier, actual diagnostic
formatter, LED bus, RGBW conversion and power limiter with fake domain getters,
clock/Print and NeoPixel transport. It checks reception/trust states, valid zero,
invalid/NaN speed, exact expiry boundaries, rollover, stale RMC despite fresh
other bytes, recovery, retained daily value/date and diagnostic counters. It
also checks initial and subsequent brightness changes, forced limiter, retained
lower budget/brightness and unchanged requested configuration. Host checks
confirm normal core ordering, welcome exclusion and queued reporting.

These tests do **not** inject live UART bytes into the firmware parser or prove
real fix/LED behavior. Existing parser/filter tests remain in the common suite.
`pio device list` returned no serial devices. Wokwi runtime remains pending
under the CLI/token limitation recorded in I0; its build/host asset tests pass.

All six ELF symbol lists and package inventories were inspected: products
exclude `bringup::`; I0/I1 exclude GPS, normal LED policy and application storage;
I2 includes normal GPS/LED/storage/Wi-Fi plus `gps_check::report`, with no I1
controller or welcome. No graphics dependencies were added. CI now has six
separate firmware targets/artifacts; local YAML/matrix validation passes,
but a remote CI run is not claimed. Documentation links and `git diff --check`
were checked. Ignored raw evidence lives in
`Platformio/Dog-RGB/artifacts/display-i2/` (build, host, packages, symbols, hashes).
